# Medical-RAG
🏥 Medical-RAG: 高可靠医疗辅助诊疗系统
📑 项目描述 (Project Overview)
一句话总结：本项目是一个面向垂直医疗领域，具备实体级知识溯源与多轮诊断追踪能力的 Agentic RAG 专家系统。
业务场景：旨在解决传统通用大模型在严肃医疗问答中面临的“缺乏循证依据（幻觉）”、“专有名词词汇鸿沟”、“长文本检索碎片化”及“多轮问诊意图漂移”等落地痛点。
核心能力：涵盖高可用离线知识库构建、实体感知嵌套分块、Dense+Sparse多路混合召回与RRF融合、交叉编码器置信度截断、绝对坐标长文本重组（Small-to-Big）、以及基于Few-Shot的大模型智能路由与查询重写。

🤖 模型基座选型
Embedding 模型 (稠密向量)：BAAI/bge-m3，支持多语言与长文本的高维语义映射。
Sparse 索引 (稀疏向量)：BM25 + jieba 分词，构建本地倒排索引，弥补医疗专有名词字面匹配短板。
Reranker 模型 (交叉精排)：BAAI/bge-reranker-v2-m3，基于Cross-Encoder输出绝对Logits关联分数。
LLM 中枢 (生成与重写)：DeepSeek-V4，使用DeepSeek-Chat API，承担逻辑推理、格式化输出与意图提取任务。

👨‍💻 核心技术贡献--系统全链路技术决策与优化
1. 数据接入层构建高可用幂等性数据管道与本地倒排索引
针对大规模向量化易触发API限流的痛点，设计了基于“指数退避重试（Exponential Backoff）+ 文本MD5哈希”的离线流。配合ChromaDB的Upsert机制实现幂等性写入，支持完全免干预的断点续传。同时将BM25序列化对象与原始文档深度绑定并持久化至本地，将系统在线启动耗时从O(N)降至O(1)。
2. 切分策略层设计实体感知的递归分块算法
摒弃传统的固定滑动窗口切分策略。设计“硬边界实体隔离 + 软边界递归字符切分”的嵌套规则。在切分时强制捕获医学实体名称，并向所有子Chunk注入包含实体名称+绝对坐标序号的强结构化Metadata标签，从源头解决长文本切分导致的语义孤儿（Orphan Chunk）问题。
3. 检索排序层实现基于RRF融合与Logits阈值截断的漏斗召回
构建了Top-20粗排到Top-5精排的检索漏斗。首先利用 RRF（倒数排名融合）算法抹平Dense与Sparse双路的异构分数差异；随后在Cross-Encoder精排阶段，提取模型输出的无界Logits绝对分数，设定物理置信度及格线。对OOD（库外提问）实施毫秒级硬拦截，显著降低无关上下文导致的大模型幻觉率与Token成本。
4. 基于全局记忆与Few-Shot的Query Rewrite引擎
在检索前置位解耦出独立的LLM路由节点。为解决多轮对话架构中“长线失忆”与“话题混淆”的经典悖论，主动摒弃了传统的滑动窗口物理截断，采用“全量历史视野（Full Context）+ Few-Shot学习”范式。通过向 LLM 注入正反对抗示例（标准指代消解 vs 强烈话题切换强制剥离），利用大模型的自注意力机制精准锚定真实意图，在保留无损长程记忆的同时，彻底压制了多轮跳跃提问时极易引发的“上下文粘连（Context Bleeding）”现象。

🧗‍♂️ 核心架构难点与解决方案
难点 1：长文本检索召回后的“语义撕裂”与“N-Chunk 乱序重排”问题
挑战：一份完整的疾病指南（包含病因、症状、药物）通常会被切分为多个Chunk。在Rerank精排阶段，模型严格根据相似性得分排序，极易导致尾部Chunk（如具体用药）得分高于头部 Chunk，造成喂给大模型的上下文发生“逻辑倒装”，干扰 LLM 的因果推理。
解决方案：引入基于局部Metadata的Small-to-Big（子块到父块）动态聚合架构。在检索器返回高分切片后，不直接投递给大模型，而是在内存构建哈希表，通过提取前期切分时注入的 [绝对坐标序号]，强制进行O(N log N)的空间位置升序排序。以细粒度切片（Small）迎合检索模型的精确召回，以绝对物理坐标还原完整拓扑（Big）迎合大模型的宏观理解，彻底消除了长文本RAG的乱序顽疾。
难点 2：业务严谨性护栏与“部分命中”场景下的逻辑死锁
挑战：严肃医疗系统通常设有“未找到依据直接拒答”的安全护栏。但面对复合型Query（如“推荐用药及居家备药方法”）时，若知识库仅命中“推荐用药”而无“备药指导”，生硬的安全护栏会导致大模型触发全局拒答机制，引发前后回答矛盾的逻辑死锁。
解决方案：引入分级响应机制进行Prompt软路由重构。在系统指令中明确区分“完全不命中”、“局部命中”与“日常闲聊”三态。规定在局部命中时，优先提炼已知文献，缺失部分允许LLM调用内部医学常识（如“处方药禁忌”）进行防御性建议，并解除全局拒答锁定。实现了系统在苛刻安全边界下的高情商交互。

🛠️ 操作步骤与使用说明
1. 环境准备
确保您的Python版本为3.10+，克隆项目后安装依赖：
pip install -r requirements.txt
2. 配置 API 密钥
在项目根目录下新建 .env 文件，并填入您的API Key：
SILICONFLOW_API_KEY="您的硅基流动密钥"
DEEPSEEK_API_KEY="您的DeepSeek密钥"
3. 构建离线知识库
运行离线脚本，系统将读取 data/ 目录下的文献，进行切分、调用Embedding模型向量化，并在本地生成 ChromaDB 向量库与 BM25 序列化索引。
python build_index.py
注：脚本内置Exponential Backoff 容错机制，若遇API限流中断，直接重新运行即可，MD5机制保证数据不会重复。
4. 启动Web辅助诊疗工作台
python web_app.py
启动成功后，在浏览器中访问控制台输出的本地地址（默认：http://0.0.0.0:7860）。
👨‍⚕️ Web 工作台操作指南
左侧控制面板：提供实时调整RAG检索参数的滑块，可动态干预底层引擎。
Top-K：控制双路粗排召回文献数量。
Top-N：控制最终送入 LLM 上下文窗口的精排文献数量。
Threshold：相似度及格线，拉高可增强防幻觉能力，过滤无关信息。
右侧诊疗中枢：支持多轮自然语言对话，系统将自动进行指代消解与意图重写。
白盒溯源功能：展开底部的 “🔍 RAG 检索链路溯源” 折叠面板，即可实时查看当前对话的 LLM 判定依据及合并重组后的知识库原文切片。

🚀 未来演进方向
目前系统基于RAG与LLM-Router实现了单向的高质量知识流转。在下一版本中，计划将其升级为完全体的 Agentic RAG。通过引入ReAct 框架，赋予系统反思与多轮迭代检索（Self-Reflective Retrieval）的能力，并在本地知识库缺失时，赋予其自主调用 Web Search API 获取最新医疗文献的外部工具执行权限。

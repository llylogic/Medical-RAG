# 在自己电脑上扮演客户，调用学校服务器上的 RAG

这是一个独立的命令行客户方项目。只需要 Python 3.9 或更新版本，不需要 pip 安装依赖，不需要 FastAPI、模型文件、知识库、服务端源码或供应商的 Key。

## 文件职责

- `main.py`：输入问题、显示答案、保留当前程序里的对话历史。
- `rag_client.py`：通过 HTTP 发送问题和服务方发放的 Key，读取返回结果。
- `启动客户端.cmd`：方便在 Windows 双击运行。

这两个 Python 文件都运行在客户电脑上。服务端的 `api.py`、`rag_api_service.py` 和 `core` 仍只运行在学校服务器上。

## 1. 保持当前已经跑通的服务

保持 EasyConnect、电脑上的龙猫云代理，以及此前在电脑本地打开的 SSH 代理通道窗口运行：

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -R 127.0.0.1:17892:127.0.0.1:7892 sxy@172.20.152.145
```

这是服务器调用模型所需的代理通道。如果它已经开着，不要重复建立。

在服务器上保持 FastAPI 运行：

```bash
bash ~/Projects/lly/rag_interview_project/start_rag.sh api
```

如果服务已经在运行，不要启动第二份。客户调用 API 不需要同时启动 Gradio Web 项目。

## 2. 确认客户电脑能访问接口

如果电脑浏览器仍能打开 http://127.0.0.1:8000/docs，沿用现有 VS Code 端口转发，保持 VS Code 的远程连接即可。

如果 VS Code 显示的本地转发端口不同，客户端地址也要使用它显示的本地端口。

如果不使用 VS Code 转发，可以在电脑本地另开一个 PowerShell 窗口，建立一个单独的接口转发通道：

```powershell
ssh -N -o ExitOnForwardFailure=yes -o ServerAliveInterval=30 -L 127.0.0.1:18000:127.0.0.1:8000 sxy@172.20.152.145
```

这时客户端填 http://127.0.0.1:18000，保持这个窗口运行。它把电脑上的 18000 端口连接到学校服务器的 8000 端口。

两种转发各有用途：`-R ...17892...` 让服务器使用电脑的代理访问模型；`-L ...18000...` 或 VS Code 端口转发让电脑访问服务器的 RAG API。

本次练习选用已有的 VS Code 转发最省事，不必额外建立第二种方式。

## 3. 启动客户项目

双击“启动客户端.cmd”。也可以在这个文件夹打开 PowerShell，执行：

```powershell
python main.py
```

程序会依次询问：

1. 服务地址：沿用目前成功的转发时，直接回车使用 http://127.0.0.1:8000。不要填写 `/docs` 页面地址。
2. 服务方 Key：粘贴服务器 `.env.api` 中 `APP_API_KEY=` 后面的值，不包含引号，不加 `Bearer`。这不是硅基流动或 DeepSeek 的 Key。

输入 Key 时不会显示字符，粘贴后按回车即可。客户端不把 Key 保存到文件，不输出到日志，也不把它写进命令历史。

随后输入问题，例如“介绍一下肌纤维组织炎”。回答后可以继续追问，或者使用：

- `/refs`：查看上一次成功问答返回的参考资料。
- `/new`：清空客户端对话记录，重新开始。
- `/health`：仅检查服务响应，不验证 Key，不调用模型。
- `/quit`：退出客户端。服务器和 SSH 通道仍保持原来的状态。

历史记录保存在当前进程内，每次问答随请求发送；退出后不会保存。当前服务允许最多 20 条历史消息、每条 8000 字符，以及问题与历史合计 32000 字符。超过限制时，客户端从最早的完整问答轮次开始移除。

## 4. 实际发送了什么

```http
POST /chat
Authorization: Bearer <服务方发给客户的 Key>
Content-Type: application/json
```

```json
{
  "message": "介绍一下肌纤维组织炎",
  "history": []
}
```

服务端返回：

```json
{
  "answer": "服务端生成的答案",
  "references": [{"title": "资料标题", "content": "资料原文"}]
}
```

这是项目自定义的 `/chat` 接口，不是 `/v1/chat/completions` 协议。客户程序按这里的格式请求即可。

## 5. 怎样算练习完成

在本地客户程序中成功完成以下操作：

1. 输入问题后看到服务端返回的答案；服务端终端出现 `POST /chat ... 200 OK`。
2. 输入 `/refs` 能看到返回资料，并能继续追问。
3. 退出后用一个故意写错的测试 Key 重开客户端，发送问题得到 `HTTP 401`；换回正确 Key 后能正常问答。

这说明独立客户程序、接口认证和 RAG 问答已经完成联调。健康检查成功本身不等于问答成功。

## 6. 真正给其他人使用还差什么

其他人的 `127.0.0.1` 指向他们自己的电脑，不能直接访问你的服务。不要把这个本机地址当成公共 API 地址发送给客户。

本次测试通过 SSH 使用校内服务器，因此服务端继续监听 `127.0.0.1:8000` 即可，无需改成 `0.0.0.0`。仅修改监听地址也不会让校内机器自动拥有公网访问能力。

正式交付时，需要由服务方提供客户可达的网络入口，例如获准的企业内网入口或公网 HTTPS 服务地址，并让服务和模型网络连接稳定运行。当前模型访问依赖你的个人电脑和 SSH 通道，适合开发联调。

现有接口只有一个共享 Key，每个进程同时处理一条 RAG 请求。多客户长期使用时，再按需要补充每客户单独的 Key、撤销与用量限制、运行监控等能力。

普通 API 客户只拿服务地址、服务 Key 和接口文档，不需要获得你们学校服务器的 SSH 账号或 RAG 源码。
